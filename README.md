# ArcAgent

A real time inbound voice agent that answers dental implant enquiry calls, qualifies the
caller, extracts an insurance signal, scores the lead deterministically, warm transfers hot
leads to a live coordinator, and books a callback with an SMS confirmation for everyone
else.

```
Twilio Media Streams  ->  Deepgram streaming STT  ->  LangGraph agent
                                                            |
Twilio  <-  Cartesia streaming TTS  <-------------------- ---+
```

mulaw 8 kHz end to end. No resampling anywhere in application code.

> **Status: in development.** Result tables are generated from the database by
> `scripts/render_eval_results.py`. Anything marked `TODO_OWNER` is filled in from a
> measured run, never from an estimate. See [CONTRIBUTING.md](CONTRIBUTING.md).

## Why

Paid search leads for high ticket dental work decay in minutes. Practices lose a large share
of inbound calls to voicemail, hold time, or an untrained front desk. ArcAgent answers every
call immediately, qualifies to the same standard every time, and gets a hot lead onto the
phone with a coordinator while the caller is still on the line.

The buyer is not a dentist. It is the agency or DSO operations lead measured on cost per
booked consultation.

## What is interesting here

**The eval harness, not the pipeline.** Thirty fixed caller personas, run on every prompt
change, with handoff precision and recall tracked separately because they are not worth the
same. `compare_runs` fails a merge that lowers handoff recall on hot buyers even if the
overall pass rate goes up.

**Scoring is deterministic.** The model is never asked whether a lead is hot. It extracts
fields; a printed rule table turns fields into a number. Identical fields always produce an
identical decision, which is the only reason a regression test on a conversation means
anything. See [docs/scoring.md](docs/scoring.md).

**Barge in is tested, not assumed.** The order of operations when a caller interrupts is
written down in [docs/turn_taking.md](docs/turn_taking.md) before it was written in code,
and the tests assert on that order. Two real concurrency bugs it caught are in
[docs/failure_modes.md](docs/failure_modes.md).

## In scope

- Inbound PSTN over Twilio bidirectional Media Streams, with webhook signature validation
- Streaming STT with endpointing, interim results, and reconnection
- A LangGraph qualification conversation with per node structured outputs
- Streaming TTS with barge in, backchannel suppression, and silence handling
- Deterministic lead scoring and routing
- Warm transfer for hot leads; callback booking plus SMS for everyone else
- Full persistence of calls, turns, leads, scores and per stage latency
- Edge paths: wrong number, existing patient, minor, Spanish fallback
- A two tier evaluation harness with run over run comparison and a dashboard

## Out of scope, deliberately

- Outbound dialling
- Practice management or EHR integration (Dentrix, Open Dental)
- Real insurance eligibility verification. The agent extracts the signal; it does not verify
  coverage
- A full Spanish conversation. Spanish is detected and routed to a callback
- Payment collection and financing applications
- Multi tenant configuration
- A HIPAA compliant production deployment. The design and every gap are in
  [docs/compliance_design.md](docs/compliance_design.md)

does not measure real world conversion, and no number here should be read as if it did.

## Limitations

- The personas and the agent prompts have one author. The harness catches regressions and
  inconsistency; it cannot tell you the agent handles a caller it has never seen.
- Tier 2 reads the agent's own utterance from the database rather than transcribing it, so
  it measures the audio path and the latency, not the agent's comprehension of its output.
- Objection detection is keyword first. It catches blunt objections without a model round
  trip and will miss subtle ones.
- No echo cancellation, no custom VAD, no retry on a failed transfer. Each is a deliberate
  omission with a reason in [docs/architecture.md](docs/architecture.md).

## Running it

```bash
cp .env.example .env                       # your own credentials, never committed
docker compose up -d                       # postgres 16
uv venv && uv pip install -e ".[dev,agent,dashboard]"
alembic upgrade head
python -m scripts.seed_slots               # two weeks of callback slots

uvicorn arcagent.app:app --reload
ngrok http 8000                            # point the Twilio voice webhook at
                                           # $PUBLIC_URL/voice/inbound
```

| Task | Command |
|---|---|
| Tests | `pytest -q` |
| Lint | `ruff check . && ruff format --check .` |
| Talk to the agent in text | `python -m scripts.repl` |
| Tier 1 eval | `python -m evals.run_text --run-name baseline --repeats 3` |
| Tier 2 eval | `python -m evals.run_audio --run-name audio-baseline --groups hot_buyers` |
| Compare two runs | `python -m evals.compare_runs <old> <new>` |
| Render the results table | `python -m scripts.render_eval_results` |
| Dashboard | `streamlit run dashboard/app.py` |
| Purge old transcripts | `python -m scripts.purge_old_data --dry-run` |

The live vendor checks are skipped by default: `RUN_INTEGRATION=1 pytest
tests/test_vendor_integration.py` runs them and costs money.

## Layout

```
arcagent/
  app.py               FastAPI: /voice/inbound, /voice/stream, /voice/echo, /admin
  telephony/           frame parsing, call session, barge in, transfer, SMS, routing
  speech/              deepgram_stt.py, cartesia_tts.py
  agent/               graph.py, scoring.py, nodes/, prompts/v<N>/, edge_cases.py
  persistence/         models, repositories, migrations
evals/                 personas/, simulator, run_text, run_audio, metrics, compare_runs
dashboard/app.py       Streamlit
docs/                  architecture, scoring, conversation design, turn taking,
                       compliance, failure modes, latency and cost, vendor params
```
