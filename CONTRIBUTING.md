# Contributing

## The merge rule

**Do not merge a change that lowers handoff recall on hot buyers, even if it raises the
overall pass rate.**

A missed handoff loses a lead that was ready to book. A false handoff costs a coordinator
two minutes. The two errors are not worth the same amount, so an average that trades one
for the other is hiding the thing that matters.

`python -m evals.compare_runs <old> <new>` enforces this. It exits non zero when a guarded
metric drops by more than the noise floor. The guards are in
`evals/compare_runs.py::REGRESSION_GUARDS`.

## Every change that touches a prompt or the graph

1. Run the harness before the change and note the run id.
2. Make the change. A prompt change is a new `prompts/v<N>/` directory, never an edit to
   an existing one, so an old run stays reproducible.
3. Run the harness again with `--run-name` describing the change.
4. `python -m evals.compare_runs <before> <after>`.
5. Put the comparison in the pull request. Not a summary of it, the table.

## Numbers

No number is typed into `README.md` or anything in `docs/` by hand. `docs/eval_results.md`
is generated by `scripts/render_eval_results.py` from the database, and it says so at the
top of the file. If a number cannot be traced to a run id or a log line you can open, it
does not go in.

This applies to latency and cost too. Measure it, or leave the `TODO_OWNER` in place.

## Owner authored files

Never edited by an agent, and changed by hand only deliberately:

- `arcagent/agent/prompts/**`
- `evals/personas/**`
- `docs/scoring.md`
- `docs/conversation_design.md`
- `docs/vendor_params.md`

## Before opening a pull request

- `ruff check . && ruff format --check .`
- `pytest -q`, with the output in the pull request
- for anything touching the audio path or cancellation, run the tests yourself and make a
  real call
